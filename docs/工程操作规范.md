## 1. 项目全景（30 秒版）

### 1.1 目标

用 **OCR 准确识别扫描版教材 PDF**，还原版面（图 / 表 / 章节结构），建成可检索的原文语料，并在桌面端 App 与离线网页里**按原文位置**呈现原文与插图。

### 1.2 六层流水线

```
① 抽取     tools/ocr_textbook.py        PDF → 分页 md + 裁切插图 + OCR 缓存
              └─ src/engine/layout.py   版面还原：行→段→标题→图区→表格
② 清洗     tools/merge_ocr_pages.py     分页 → 整册（剔目录页 / 修页码 / 附录归一）
③ 语料     tools/build_corpus.py        整册 → corpus.json（词法语料）
              └─ src/engine/retrieval.py 标题索引 + BM25 + AND→OR 降级 + DF 拒答
④ 阅读     src/engine/textbook_reader.py 按章节取「保序块序列」
              └─ src/services/study_service.py  渲染 HTML（<img>/<table>）
⑤ 交付     tools/build_reader.py         整册 → data/reader.html（单文件离线）
              └─ src/main.py             PySide6 QTextBrowser 内嵌
⑥ 验收     build/acceptance.py           检索 9 条 + 插图落位 + 表格结构
```

**单向依赖**：②不回头改①，③不回头改②。任一层的产物都是下一层的**输入契约**。

### 1.3 当前实测基线（2026-09-16）

| 指标 | 数值 |
|---|---|
| 整书 | 485 页（上半 250 + 下半 235） |
| 插图落位 | **296 / 296 = 100%** |
| 表格还原 | **93 张，结构合格 93 / 93 = 100%** |
| 检索验收 | 9 / 9 通过（含拒答、AND→OR 放宽、跨页落位） |
| 阅读器 | 241 节 / 1459 片段 / 296 图 / 93 表 / 页码 1–474 |
| 单册全量 OCR | 上半 1163s、下半 1071s（≈4s/页） |
| 单册缓存重放 | 上半 **24s**、下半 **14s**（≈ 50–76 倍加速） |

> 这条基线是**回归基准**。任何改动后跑一次 §9 的验收清单，数字低于上表即视为回归。

### 2.6 数据来源与合法渠道（重要 · 产品价值观）

**软件只接受合法获取的教材内容。** 网上流传的整本教材 PDF 绝大多数是盗版，本项目不下载、不收录盗版副本——这既是产品价值观，也避免使用者承担法律风险。

**合法来源三类**：① 自己合法拥有的教材（实体书扫描件 / 学校发放电子版 / 购买的正版电子书）；② 出版社官方配套资源（课件 PPT、试读章节）；③ 高校教学平台公开共享的官方课件。

**入库流程**：

## 4. 六条铁律

> 全部是踩坑踩出来的，每条都对应 §6 里至少一个真实案例。

### 铁律 1 · 先建反馈循环，再改代码

**做**：改任何判据前，先有一个能在**秒级**告诉你"改好了没有"的度量。
**反例**：改一次版面判据 → 跑 34 分钟全书 OCR → 看图 → 不对 → 再改 → 再等 34 分钟。（早期真实经历）
**正例**：先写 `build/probe_boxes.py` dump 单页坐标 → 改判据 → 单页跑 → 秒级出结果。

排查的固定循环：**复现 → 缩小 → 假设 → 埋点 → 修 → 回归测试**。

### 铁律 2 · 改判据前先落盘原始数据

**做**：把"上一层的原始观测"缓存到磁盘，判据层每次从缓存重放。
**实现**：`data/ocr_cache/<册>/page_NNNN.json` 存 **RapidOCR 原始框**（不是版面结果！），改 `layout.py` 后秒级重放。
**收益实测**：250 页从 1163s → **24s**；235 页从 1071s → **14s**。
**关键细节**：缓存必须存**最原始**的观测。若存了"判据后的结论"，改判据时会读到旧结论，缓存反而变成陷阱。

### 铁律 3 · 先改代码，再启动长任务

**做**：代码修改**完成并落盘**后，才启动批量/后台任务。
**为什么**：Python 进程在**启动时就 import 并定型了模块**，之后再改源文件**对已运行进程无效**。
**真实事故**：OCR 任务 09:16:12 启动，`layout.py` 09:25:08 才改完 → **整批 485 页全部用旧判据**产出（症状：图题在前、图在后，与"图在上、图注在下"的原书顺序相反），整批作废。
**补救**：有缓存时重放即可（24s）；无缓存则整批重跑（34 分钟）。

### 铁律 4 · 一次只改一个变量

**做**：同一次实验只改一个判据，且用**同一批样本**对照前后。
**为什么**：一次改三处，结果变好/变坏都不知道该归因给谁；下一轮又会推翻上一轮的结论。
**本项目实践**：三张漏图是**三种不同的失败模式**（A 触右缘 / B 左对齐被吞 / C 图题不居中），必须逐一定位、逐条编号，而不是笼统说"图内文字被误判"。

### 铁律 5 · 全局判断放到最晚、最全局的层

**做**：判断"这一页是不是目录页 / 这一册有没有附录"这类**需要整书视野**的事，放在**合并层**（②），不要放在分页层（①）。
**为什么**：
- 分页层一次只看一页，判不准"这页在全书里的角色"；
- 放在合并层，**改判据只需重跑合并（秒级），不必重跑 OCR（半小时）**。

### 铁律 6 · 新增之前先做减法

**做**：先剔除（目录页 / 页脚 / 边栏 / 图内文字 / 重复块），再新增结构（表格 / 附录层级）。
**脏数据处置**：**归档，不删除**。移到 `build/fig_experiments/` 之类的目录，保留可追溯性。
**反例**：`data/figures/` 根目录混入 7 个实验残留文件，与正式产物 `data/figures/<书名>/` 同处一层，污染交付目录。

## 5. 难问题排查规程

### 5.1 症状分类表（第一件事：归类）

| 症状 | 大概率是 | 先看哪里 |
|---|---|---|
| 结果**完全为空** / 报错 | 接口错（契约不匹配） | 上下游的数据结构是否一致（如 `{"book","tree"}` 包壳没展开） |
| 结果**有但错位**（图跑到章尾、标题挂错父级） | 判据错（顺序/层级逻辑） | 块序构造处、标题栈、插入位置 |
| 结果**对大部分、错少数** | 边界条件（少数页面版式特殊） | dump 出错那几页的原始坐标 |
| 结果**每次都不同** / 调不动 | 读了旧产物（缓存/mtime/进程 import） | 产物 mtime vs 源码 mtime；是否有缓存 |
| **改了没效果** | 改的地方不是生效路径 | 搜全项目确认调用链；是否有第二处实现 |
| 同类问题**修了又出现** | 抽象层级选错（应有公共函数） | 是否有 N 处复制粘贴同一段逻辑 |

### 5.2 卡住时的固定动作（按顺序做，别跳）

1. **别猜，先 dump。** 把出问题那一步的**输入**和**输出**都打印出来。证据 > 推理。
2. **缩小样本。** 全书 → 一册 → 一页 → 一张图 / 一个表。缩到能秒级复现为止。
3. **分层对照。** 逐层打印中间产物（原始框 → 合并行 → 图区 → md），看**哪一层开始不对**。
4. **假设要有编号。** 写成"H1: …，验证方法：…"，验证完标注成立/推翻。别让假设在脑子里飘。
5. **查"是不是旧数据"。** 对 mtime；查缓存；确认进程是什么时候起的。
6. **搜全项目找同款。** 一个 bug 常常有 2–4 个同款副本（本项目标题栈缺陷在 3 处重复出现）。
7. **修完立刻加回归测试。** 否则下次改别处又会踩回来。

### 5.3 提高迭代速度的四个手段

| 手段 | 效果 | 本项目实例 |
|---|---|---|
| **缓存中间结果** | 分钟级 → 秒级 | OCR 原始框落盘，改动重放 24s |
| **抽小样本** | 全量 → 20 页 | 第2章 25 张图做图片提取实验 |
| **离屏渲染** | 手动验 → 自动验 | `QT_QPA_PLATFORM=offscreen` 自动数"图片真实加载数" |
| **脚本自带日志落盘** | 免 shell 编码坑 | Python stdout 走 cp936，`--log` 直接落 UTF-8 文件，不经 shell 重定向 |

### 5.4 不可行路线（黑名单 · 已排除，别再试）

> 这些不是"没想到"，是**试过/评估过并已排除**的。重试=浪费时间。

#### A. 表格与版面

| 路线 | 排除原因 |
|---|---|
| PyMuPDF `find_tables()` / pdfplumber / camelot | **纯扫描件无文本层**，它们全靠文本层坐标，直接失效 |
| Docling / Unstructured | 同上，纯扫描件上失效 |
| MinerU 2.5 / PP-StructureV3 / PaddleOCR-VL | 效果最好，但是**整页版面引擎**（数百 MB、建议 GPU），引进来等于替换自研 `layout.py`，且要全书重跑+校对 |
| olmOCR（Allen AI）/ DeepSeek-OCR-2 | 需 **7B VLM + GPU**，本机硬件不满足 |
| Marker + Surya | ~500MB，CPU 可跑但需重跑全书，性价比低于自研列聚类 |
| "引入 RapidTable 就有表格了" | RapidTable 输入是**已裁好的表格图**，它**不做表格区域检测**；区域检测仍需自研 → 引入它只解决一半问题 |

**本项目采用的路线**：**自研列聚类**（`layout.py::detect_tables`）。依据：扫描版表格的**每个单元格本来就是独立 OCR 框**，列起点跨行重复 → 根本不需要结构识别模型。

#### B. 图片

| 路线 | 排除原因 |
|---|---|
| 用 VLM 描述图内容再入编 | 有**幻觉**风险 + 可能遗漏，用户明确不接受 |
| **采用**：按坐标从 PDF **裁切** | 零识别误差、零幻觉；`data/figures/<书名>/page_XXXX_figN.png` |

#### C. 检索

| 路线 | 排除原因 |
|---|---|
| chroma 默认 embedding（all-MiniLM-L6-v2） | `DOWNLOAD_PATH` 硬编码到 `C:\Users\...\`，违反"不占 C 盘"；且是英文模型 |
| chroma 自带 `chroma_bm25` | 缺 `snowballstemmer`；英文停用词 + 按空格切分 → 中文整句变成一个 token |
| "按 IDF 砍词重试" | **死逻辑**：BM25 本身是 OR 语义，减少查询词不会带来新结果 |
| **采用**：标题索引 + BM25，**AND → 无结果降级 OR**；拒答用 **DF=0** 硬判据 | 见 §6 案例 B-7 / R-3 |

#### D. 工程习惯

| 反模式 | 原因 |
|---|---|
| 测试写真实数据目录 | 污染用户数据。改用独立课程名 / 临时目录 / 快照-还原 |
| 用 `except Exception: return 0` 静默兜底 | 会把**真异常**吞掉（本项目 `delete_textbook` 因此静默失效很久） |
| 一次改动碰三个文件 | 无法归因 |
| 长任务前台等 | 阻塞；应后台跑（`run_in_background`） |

### 5.5 三个"看起来像 bug 其实不是"的判断

避免误伤，先排除这三类：

1. **附录习题解答的"第1章…第9章"**——不是顺序错乱，是书末附录A 的习题答案，本就该挂在附录下。
2. **语料块数从 1702 涨到 2485**——不是异常，是 `list_books()` 同时命中了"课件版.md"（第三本）。
3. **`data/backup/` 里的旧文件**——是设计的回滚点，不是垃圾。

## 6. Bug 案例库（按症状检索）

> 格式统一为：**症状 → 根因 → 修法 → 教训**。可直接作为 review/交接材料。

### 6.1 版面还原（`layout.py`）

#### L-1 少数图漏检（4 张）
**症状**：296 张图里漏 4 张（p24 图1-7、p159 图4-30、p160 图4-31、p181 图4-47）。
**根因**：**是三种不同的失败模式，不是一个 bug**。
- **A** 图内小图题刚好触右页边（x1=1250 > 0.85W=1237.6）→ 被当成正文行 → 图区上边界被推高 → 高度 < 70px 被丢弃。
- **B** 图内左对齐文字（PING/tracert 截图）被"吃掉本段收尾行"循环整段吞掉（x0≈216 < 旧阈值 318.6）→ 上边界穿过整张截图。
- **C** 图题本身不居中（偏差 119 > 0.06W=87）→ 被"必须居中"的必要条件直接否掉。
**修法**（统一"正文行"判据）：
- `is_body_row(r) = r.x1 > 0.85W` **且** `r.x0 < 版心左边距 + 0.05W`（两端都到边才是正文行）；
- "居中"由**必要条件降为加分项**，不居中时要求 `w < 0.36W`；
- 收尾行循环阈值由 `0.22W` 换成 `版心左边距 + 0.05W`。
**教训**：**先分类再修**。把三个模式当一个问题修，会反复改来改去。

#### L-2 图片退化成"统一堆在页尾"
**症状**：图不在原文位置，跑到页尾。
**根因**：图区被从行流切走后，**图上方的正文行和图下方的图题行变成相邻并粘成一段** → `_insert_before_caption` 的"整段精确匹配"失效 → 退化为追加页尾。
**修法**：精确匹配失败后，**按图题在段内的位置把段落切开**，拼成「前文 / 图 / 图题 / 后文」。
**教训**：插入类操作要有**退化路径**，且退化路径本身要被验证（当时只测了正常路径）。

#### L-3 图题与图的先后顺序反了
**症状**：md 里是"图题 → 图"，而书里是"图 → 图题（图注在图下方）"。
**根因**：**进程 import 语义**——OCR 任务启动早于 `layout.py` 的修改时间，整批用了旧语义。
**修法**：重放（缓存命中，24s）。
**教训**：见铁律 3。**改完代码再启动长任务**。

#### L-4 图内左对齐文字混入正文
**症状**：图内的标注文字跑到正文段落里。
**根因**：旧判据用"偏离左边距 > 7%"剔除图内文字，差 1px 就漏。
**修法**：改用**图区几何 + 窄框双条件**（`_strip_figure_lines_by_region`）。
**教训**：**阈值型判据天然脆弱**，能用几何包含关系（"在不在图区矩形内"）就别用距离阈值。

#### L-5 图表区域上边界吃掉上一段收尾行
**症状**：裁出来的图顶部多含 1–2 行前一段正文。
**根因**：图区上边界取"最近的够宽正文行"，而图内横跨大半页的标注行也"够宽"。
**修法**：通栏判据从"够宽"改为"**触到右页边**"（正文行从左边距起到右页边止；图内标注碰不到右页边）。
**教训**：**选更本质的判据**。"宽度足够"是表象，"两端到边"才是版式的本质。

#### L-6 下拉不出段落 / 整页并成一段
**症状**：段落被切碎，或整页变成一段。
**根因**：页左边距用**众数**统计，遇到表格页/图页会失真；且未处理"上一行非通栏 → 另起段"。
**修法**：左边距改用**实质行最小左界**（`_left_margin`）；补"上一行非通栏→另起段"条件。
**教训**：**统计量要选抗干扰的**（最小/最大 > 众数/均值）。

### 6.2 分页合并（`merge_ocr_pages.py`）

#### M-1 目录页没被剔除，混进语料
**症状**：检索先命中目录页；同一章节出现两次。
**根因**：`looks_like_toc` 只数 `#` 标题行、看长行当"实质正文"。而加 `(?![\d.\s])` 后，目录项 `6.5.4 邮件读取协议POP3和IMAP` 不再是标题，又被 `detect_tables` 变成表格行 → 长表格行被算成"实质正文" → `body > 1` → 判定失败。
**修法**：`looks_like_toc` 把**表格行一律排除出正文计数**；首格是章节号的表格行计入标题计数。
**教训**：**改动是有连带效应的**。改 A 层判据时，要检查 B 层有没有依赖 A 层的输出形状。

#### M-2 页码倒挂（134 处，最大差 911）
**症状**：页码忽大忽小。
**根因**：OCR 误读页脚数字。
**修法**：`_estimate_offset`（`印刷页 − PDF序` 取众数）+ `_clean_page_numbers`（超出容差 3 的用 `idx+1+offset` 覆盖）。
**教训**：让**全书的多数派**来纠正**个别的少数派**。

#### M-3 附录与正文同级 → 知识树混排
**症状**：知识树里"第1章"排到最前，点开是习题答案。
**根因**：书末"附录A部分习题的解答"那行**没被识别成标题**，其内部 `# 第1章…第9章` 与正文 `# 第6章应用层` 同为 h1。
**修法**：`normalize_appendix` 取**第一个"其后 ≥2 条裸第N章"的附录行**（不能取最后一个——书末还有附录B/C）→ 升为一级，其后裸章降为二级。
**教训**：**"取最后一个"是危险的启发式**。要找"结构上说得通"的那个，而不是位置上的那个。

### 6.3 检索与切块（`retrieval.py` / `knowledge_base.py`）

#### R-1 标题栈弹栈判据错误 → 章节落位错（**同一 bug 有 3 个副本**）
**症状**：`三次握手` 的 `section_path` 变成 `5.8.2… > 5.9… > 5.9.1…`，多了一层错误父级。
**根因**：弹栈条件写作 `len(stack) >= level`。下半册从 `### 5.8.2` **半途开始**（第5章起于上半册），栈里第一项 level=3；再来 `## 5.9` 时 `len(stack)=1` 不满足 `>=2` → 弹不掉 → 5.9 被错挂到 5.8.2 下。
**修法**（**三处同修**）：
1. `retrieval.parse_markdown`：增加与 stack 平行的 `levels`，按 `levels[-1] >= level` 弹栈；
2. `retrieval.infer_chapter("5.9TCP的运输连接管理") → "第5章"`：栈为空时补章级祖先；
3. `study.build_knowledge_tree` 与 `knowledge_base._split_markdown_by_headings` 同款修复。
**教训**：**用 `len()` 当层级是错的**——层级是值，不是长度。且**一个逻辑复制到 N 处就会有 N 个同款 bug**，修完必须全项目搜一遍。

#### R-2 `量子纠缠` 没被拒答
**症状**：问书外概念，返回"量子密码"段落 → 用户误以为书里讲过。
**根因**：教材第 7 章有"量子密码"顺带 1 次"量子"，"纠缠" 1 次是上半册 ARP 注脚的 OCR 误识。"量子" DF=3、"纠缠" DF=1 → 全都不为 0 → DF=0 判据失效。
**修法**：新增**拒答判据二**：查询有 **≥2 个实词**，且**每个命中词**全库 DF ≤ 2 → 拒答。落地在"每个命中词都极罕见"上，不误杀"OSI 七层模型"（"模型" DF=16）。
**教训**：**拒答不能只有一条判据**。DF=0 挡"完全不存在"，判据二挡"只是顺带命中字面"。

#### R-3 检索分数恒为 0（历史遗留）
**症状**：所有命中分数都是 0.0。
**根因**：chroma 集合距离度量是 `l2`，embedding 是单位向量 → 真实距离 ∈[0,4]；而代码算 `max(0, 1-dist)` → 恒 0。v0.4 报告声称"已修"，实际只是把负数截断，**掩盖了"距离度量用错"**。
**修法**：改用排名 + 拒答判据，**不用绝对阈值**；UI 不再显示绝对百分比（RRF 分数无物理意义）。
**教训**：**"截断/兜底"式修复会掩盖根因**。"让值不为负"不等于"值是对的"。

#### R-4 切块粒度不当导致内容被截断
**症状**：长块被模型截断，丢内容。
**根因**：块均长 787 字，而 `bge-small-zh-v1.5` 位置上限 512（中文约 1 字≈1 token）→ 丢约 37%。
**修法**：目标块长约 400 字 + 60 重叠 + 自然边界。
**教训**：**模型约束要前移到数据设计**，不要等检索效果差才回头查。

#### R-5 `delete_textbook` 静默失效
**症状**：删除教材向量块没生效，库里留残留。
**根因**：chromadb 的 `where` **不支持多键并列**，必须 `$and` 包裹；代码传 `{source_file, course}` 直接抛 `ValueError`，又被 `except Exception: return 0` **吞掉**。
**修法**：改为 `$and` 单键条件；**去掉无差别兜底**。
**教训**：**`except: return 0` 是 bug 放大器**。要么让它抛，要么至少记日志。

### 6.4 测试与数据安全

#### T-1 测试污染真实数据
**症状**：跑完测试，真实错题本/题库被改动。
**根因**：
- `test_knowledge_base.py` 把测试文档塞进**真实课程**语料再断言 → 必然被真实教材压过（断言不可能成立），还污染向量库；
- `test_practice.py` 会**覆盖真实题库文件**、动真实错题本（"答对即移出"会删掉用户已有记录）。
**修法**：
- `test_knowledge_base.py` 改用**独立课程名**隔离 + 收尾 `delete_textbook` 清理；
- `test_practice.py` 加**快照—还原**；
- 测试文档每章写 ≥200 字（否则会被"小块并入前一块"规则合并，断言无法成立）。
**教训**：**测试的默认环境应该是隔离的**。"跑个测试"不应该有副作用。

#### T-2 断言太弱，P0 长期逃逸
**症状**：检索错章节，测试却通过。
**根因**：`test_knowledge_base.py` 只断言"有结果"，不校验"结果对不对"。
**修法**：断言改为"命中章节必须包含查询主题"。
**教训**：**只断言"非空"等于没测**。断言要能区分对错。

#### T-3 验收脚本没有拒答维度
**症状**：拒绝了该拒的，但脚本不检查。
**修法**：`acceptance.py` 加**预期状态**用例（`status=ok` / `status=not_found`）+ 关键词校验。
**教训**：验收用例要覆盖**否定路径**（该拒绝的必须拒绝）。

### P1 · 难 bug 诊断（反馈循环优先）

Step 6 全量验证：跑 build/acceptance.py --log build/accept_<改动名>.log。

【输出格式】

## 10. 附录

### 10.1 关键设计决定（Why，供 review）

| 决定 | 理由 |
|---|---|
| 图片**裁切**而非识别 | 零幻觉、零遗漏，规避 VLM 描述风险 |
| 表格用**列聚类**而非模型 | 扫描版每格本就是独立 OCR 框，列起点跨行重复，不需要结构模型 |
| 标题**单独成块** | chunk 级 BM25 分不清"主题块"与"顺带提及块"，标题是唯一带主题信息的字段 |
| **AND → OR 降级** 替代"砍词重试" | BM25 本身是 OR 语义，砍词是死逻辑 |
| 拒答用 **DF 判据**而非相似度阈值 | 硬、可解释、不受分数标度影响 |
| 判"整页是什么"放**合并层** | 需要整书视野；且改判据只需重跑合并（秒级） |
| 阅读器渲染**保序块序列** | 不做分类聚合，图才能落在原文位置 |
| OCR 缓存存**原始框** | 存结论会让改判据时读到旧结论 |

### 10.2 术语表

| 术语 | 含义 |
|---|---|
| L1 / L2 / L3 | 版面还原的三级：L1 行聚类、L2 表格还原、L3 章节结构重建 |
| 保序块序列 | heading/para/figure/table 按原文顺序排列、不做分组聚合的块列表 |
| 版心左边距 | 正文区域的左边界（用实质行最小左界估计，非众数） |
| DF | Document Frequency，某词出现在多少个块中 |
| 触右页边 | 行的右边界 x1 > 0.85 × 页宽 —— 判"通栏正文行"的本质判据 |
| 缓存重放 | 从 `data/ocr_cache/` 读原始框，重跑版面判据（秒级） |
