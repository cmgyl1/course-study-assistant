## 一、产品定位与范围

### 1.1 一句话定位

面向**在校生**的个人学习工作台：把教材、课件、题库等资料统一收进本地知识库，提供**自学、复习、刷题、期末冲刺**全流程辅助。数据与 AI 能力本地运行，**教材内容作为权威依据**，杜绝 AI 胡编乱造。

### 1.2 目标用户与课程

- 用户：在校生（自主学习者），单机使用
- 首批 4 门课：

  |---|---|---|
  | 计算机网络 | 《计算机网络》第8版（谢希仁） | ✅ **已完整落地**（485 页扫描件，六层流水线闭环） |
  | UML2 面向对象分析与设计 | 第2版（谭火彬，清华大学出版社） | ⏳ 待接入 |
  | 软件工程导论 | （薛继伟主编，哈工大出版社） | ⏳ 待接入 |
  | 算法设计与分析 | 第3版 | ⏳ 待接入 |

### 1.3 功能模块（按优先级）

| 模块 | 内容 | 优先级 | 状态 |
|---|---|---|---|
| 资料管理 | ① 教材库（PDF→Markdown 入库、检索浏览）② 课件归档（PPT/PDF/Word 拖入自动转格式入库）③ Word 版教材批注（生成 .docx 交 Word/WPS 批注后归档） | 核心 | ✅ 已实现；教材走新六层流水线 |

| 课程同步 | 手动课表 + 周计划 | 待办 | ⏸ 预留（`reserved/course_sync/`） |
| 移动端 | iPad/Android 伴学 | 待办 | ⏸ 预留（`reserved/mobile/`） |

### 1.4 数据组织约定（关键，不可违反）

- **教材知识库与题库物理分离**：独立存储、独立检索，互不混放。
- 教材：PDF → Markdown 章节化 → 检索语料（词法 BM25 为主，语义向量为可选增益）。
- 题库：按科目分文档（选择/填空/大题分区），**来源可溯源**。
- 错题本、批注文件：独立目录（`data/wrong_book/`、`data/annotations/`）。
- 数据来源合法性约束见 `docs/工程操作规范.md` §2.6。
- 预留位：`reserved/ai_assistant/`、`reserved/course_sync/`、`reserved/mobile/` —— 后续添加模块直接落位，无需重构。

## 三、目标架构

### 3.1 设计原则（来自 codebase-design）

1. **深模块优先**：小接口 + 多实现。给调用者高 leverage，给维护者高 locality。
2. **接缝处可替换**：AI 引擎、向量库、文档转换、题库格式都应在接缝处适配，未来可整体替换不波及调用方。
3. **失败模式显式**：每个模块的接口文档应包含错误传播约定（哪些异常会上抛、哪些会被吞）。**严禁 `except: return 0` 静默兜底**（曾因此让 `delete_textbook` 失效很久，见案例 R-5）。
4. **删除测试**：若删除一个模块后复杂度消失了 → 它是个 pass-through，不该存在。

### 3.3 核心接缝（关键接口）

```python
# 1. 检索与向量化（infra/retrieval + infra/embeddings）
#    ⚠️ 目标设想，当前**尚未抽取**：BM25 直接实现在 engine/retrieval.py，
#    零依赖、不需要适配层。等 v0.6 真正引入第二个检索实现（bge 语义路 + RRF 混合）
#    再抽这一层 —— 这正是"出现 2 个实现再抽接缝"原则的应用。
class Retriever(Protocol):
    def search(self, question: str, top_k: int) -> dict: ...
    def stats(self) -> dict: ...

class Embedder(Protocol):
    def __call__(self, texts: list[str]) -> list[list[float]]: ...
    @staticmethod
    def name() -> str: ...   # 用于冲突检测

# 2. AI 引擎（infra/llm）
class LLMEngine(Protocol):
    def is_available(self) -> bool: ...
    def answer(self, prompt: str, *, timeout: int = 120) -> str: ...

# 3. 文档转换（infra/converter）
class DocConverter(Protocol):
    def convert(self, src: Path, out_dir: Path) -> Path: ...

# 4. 题库 / 错题存储（engine/question_bank）
class QuestionStore(Protocol):
    def load(self, course: str) -> list[dict]: ...
    def index(self, course: str) -> int: ...
    def wrong_book(self) -> WrongBookAPI: ...

class WrongBookAPI(Protocol):
    def add(self, key: str) -> None: ...
    def mark(self, key: str, correct: bool) -> None: ...
    def list(self, course: str = "") -> list[dict]: ...
```

**两个适配器原则**：当某个接缝只有 1 个实现时，那是**假接缝**（过度设计）；当出现 2 个实现时（如未来切 FAISS / 加云端 LLM），才值得正式抽出 Protocol。

> 应用示例：`retrieval.py` 与 `knowledge_base.py` 曾是**两条检索链路**（词法 BM25 / n-gram 向量）。
> 2026-09-23 之前 UI 接的是后者 → 质量崩坏（案例 R-6）；现已统一到 BM25。
> 抽 `Retriever` Protocol 的时机因此**推迟到 v0.6 引入真语义向量时**（见附录 A）。

### 3.4 配置与发现

`engine/config.py` 当前硬编码 `COURSES`（4 门课 + 教材名）。v0.6+ 升级方案：
- 课程清单从 `data/courses.yaml` 加载（增减课程无需改代码）
- 单一配置入口 `Config` 对象，所有模块按需注入（而非全局导入）

### 3.5 测试策略

| 类型 | 位置 | 用途 |
|---|---|---|
| 单元测试 | `tests/unit/` | engine 纯逻辑（解析、检索、打分） |
| 集成测试 | `tests/integration/` | service 编排（模拟 UI 输入） |
| 冒烟测试 | `tests/`（当前，10 个） | 端到端可用性 |
| UI 离屏测试 | `tests/ui/` | `QT_QPA_PLATFORM=offscreen` 验证图片真实加载 |

**强制**：
- 测试**不得写入共享数据目录**。用 `tempfile.TemporaryDirectory`、独立课程名隔离，或**快照—还原**。
- 断言必须能**区分对错**（只断言"非空"等于没测，见案例 T-2）。
- 验收用例必须覆盖**否定路径**（该拒答的必须拒答，见案例 T-3）。

## 五、迁移原则（重要）

### 5.1 渐进式

- **不一次性重写**：每版本只重写"能带来最高 leverage 的那一层"
- **保持可运行**：每版发布前必须有可启动的 `大学生软件.exe`（2026-09-23 起落在**项目根目录**，与 `README.md` 同级，便于查找；旧版曾落在 `dist/`）
- **接口先于实现**：先定义 Protocol，再写适配器，最后改调用方

### 5.2 兼容性

- 数据格式（教材 md / 题库 md / `wrong_book.json`）保持向后兼容
- 添加新字段时使用 JSON 容错（缺字段当默认值）
- 旧版本 exe 写入的数据能被新版本读取

### 5.3 可逆性

- 每版保留 `data/backup/<日期>/` 目录至少 30 天（**不是垃圾，是回滚点**）
- 重大 schema 变更前必须先出迁移脚本 `tools/migrate_<from>_to_<to>.py`
- **产物可重放**：`data/ocr_cache/` 保留原始 OCR 框，改版面判据可秒级重放；**不要删缓存**

## 六、对未来开发者（或未来的自己）的提醒

1. **改完代码再启动长任务**：Python 进程启动即定型模块，之后再改源文件对运行中进程无效（曾致 485 页整批作废）。详见规范铁律 3。
2. **测试不要写共享数据**：用临时目录 + 显式清理 / 独立课程名 / 快照-还原。
3. **新增 engine 模块前先想 Protocol**：如果只是包了一层函数调用，那是 pass-through，不该存在。
4. **改设计系统先改 token 再改用法**：新增颜色/字号先在 `ui/style.py` 顶部加 token，再在 QSS 引用。
5. **教材导入后必须验证语料**：跑 `python tools/build_corpus.py --course <课程>` 看切块数与均长，再用 `tests/test_retrieval.py` 抽查命中质量。（原 chroma 时代的 `check_knowledge_quality.py` 已随依赖归档到 `tools/archive_2026-09-23/`）
6. **改判据先 dump 坐标**：`python build/probe_boxes.py --pages <页码>` 拿到原始框再动手；判据优先用**几何包含关系**而非距离阈值。
7. **一处 bug 常有 N 处同款**：本项目"标题栈弹栈"缺陷在 3 个文件里重复出现，修完必须全项目搜一遍。
8. **本地大模型方案已否决**：Ollama 等本地 LLM 方案于 2026-09-16 决定**不采用**，方案材料已清出文档，**不要再提、不要再评估**（理由见附录 B）。「答疑」模块仍保留 `reserved/ai_assistant/` 预留位，底座待定。

## 附录 A、语义检索升级路线（向量路清单）

> 现状（2026-09-23 起）：全项目**只有一条检索路** —— `retrieval.py` 的标题索引 + BM25，
> 零依赖、零下载。原先并存的 chroma + 自研字符 n-gram 哈希向量（`NGramEmbeddingFunction`）
> 已整体拆除：实测它 `score` 恒为 0（排序信息丢失）、语料仅覆盖全书 15.4%，
> 属于**词法向量的劣化实现**，并不是语义向量（案例 R-6 / R-7）。
> 因此向量路属于**增益项而非救命项**：当前 AND→OR 放宽已能命中多数改写问法。

**升级清单（按序执行）**：

| # | 步骤 | 说明 |
|---|---|---|
| 1 | 新增 embedding 路 | 用 **`bge-small-zh-v1.5`**（约 95 MB；ONNX/int8 可压到 ~24 MB）；与 BM25 **并行**，不是替换 |
| 2 | 选依赖 | 用 `onnxruntime` + `tokenizers`，**避免拖 torch**（会超 100 MB 红线） |
| 3 | 建索引 | 语料复用 `retrieval.build_from_markdown_files` 的切块结果 → 全量嵌入（秒级）→ 查询用同模型编码 → 余弦距离 |
| 4 | 混合检索 | BM25（精确术语）+ 向量（近义/改写）→ **RRF 或加权融合**；抽 `Retriever` Protocol |
| 5 | 验收 | 加"近义改写问法"用例（如"为什么两次握手不够"→ 应命中 5.9.1） |

**同时需处理的已知约束**：当前块均长 787 字，而 `bge-small-zh-v1.5` 位置上限 512（中文约 1 字≈1 token）→ 会丢约 37%。
故第 3 步应把目标块长调整为 **约 400 字 + 60 重叠 + 自然边界**（见案例 R-4）。

## 附录 B、关键技术决定（Why，供 review）

| 决定 | 理由 |
|---|---|
| 图片**按坐标裁切**而非识别 | 零幻觉、零遗漏，规避 VLM 描述风险 |
| 表格用**列聚类**而非结构模型 | 扫描版每格本就是独立 OCR 框，列起点跨行重复，不需要模型 |
| **不引入** MinerU / PP-StructureV3 / Docling | 整页版面引擎（数百 MB、建议 GPU），等于替换自研 `layout.py`。评估记录见 `docs/工程操作规范.md` §5.4 |
| **不引入本地大模型**（Ollama / qwen2.5 等） | 已否决（2026-09-16）：约 7.5 GB 磁盘 + 数 GB 显存，7B 质量仅"够用"，与「教材原文为权威依据」的定位相比收益比不高；检索与提纲已由 BM25 + 规则实现，AI 属增益项。方案材料已移除，**勿重启** |
| 标题**单独成块** | chunk 级 BM25 分不清"主题块"与"顺带提及块"，标题是唯一带主题信息的字段 |
| **AND → OR 降级** 替代"砍词重试" | BM25 本身是 OR 语义，砍词是死逻辑 |
| 拒答用 **DF 判据**而非相似度阈值 | 硬、可解释、不受分数标度影响 |
| 判"整页是什么"放**合并层** | 需要整书视野；且改判据只需重跑合并（秒级） |
| 阅读器渲染**保序块序列** | 不做分类聚合，图才能落在原文位置 |
| OCR 缓存存**原始框** | 存结论会让改判据时读到旧结论，缓存反成陷阱 |
